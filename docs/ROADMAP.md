## 分阶段交付

近期优先目标已于 2026-09-21 调整为**公开测试版**：alpha.3 已于 2026-10-06 公开发布并完成 demo 同步，见[发布完成记录](validation/2026-10-06/alpha3-publication.md)。后续继续收集试用反馈，按候选完成核心用户路径、安装升级与回退验收。执行范围、门禁及未完成项见 [公开测试版计划](PUBLIC-ALPHA.md)。完整 1.0 目标继续保留，公开 alpha 不要求先完成全部 5.7.0 对齐，也不代表 M1/M2/M3 已验收。

| 阶段 | 范围 | 完成条件 |
| --- | --- | --- |
| M0 / 0.1 alpha | 独立主题身份、可重复构建、迁移工具、真实 Halo 基础可用性 | 能独立安装/升级；旧配置不被覆盖；核心页面和资源实际可用；留有验收记录 |
| 近期 / 公开 alpha | 核心页面与交互、官方搜索评论、安装升级回退、公开试用材料 | [公开测试版门禁](PUBLIC-ALPHA.md)通过；已知限制明确，维护者确认发行渠道和实际发布 |
| M1 / 0.2 | 首页、导航、文章列表、文章排版、侧栏、深色模式、手机布局 | 与 5.7.0 固定样例在相同内容/视口/配置下逐项比对；相关交互通过 |
| M2 / 0.3 | 搜索、评论、链接/图库/瞬间及 Halo 2.26 插件页面公共布局 | 插件有无、启停和公共布局都验证；明确支持版本与替代能力 |
| M3 / 私有 RC | 全部适用 5.7.0 能力、配置文档、升级回退、浏览器/真机、无障碍与性能、供应资源 | [1.0 工程验收合同](RELEASE-ACCEPTANCE.md)全部必需场景通过；精确提交独立审查与 CI、实际私有候选包证据完整 |
| 1.0 正式发布 | 公开反馈、维护者最终验收与稳定发布 | 仓库已公开并保留完整 Git 历史；保留原公开反馈和公开仓库 CI 条件；正式 1.0 由用户确认，不由私有 RC 自动触发 |

完整能力状态以 [5.7.0 功能矩阵](parity/MATRIX.md)及其 `matrix.json` 真相源为准；双站重建方式见 [对照环境](COMPARISON-LAB.md)。以下为接手时的摘要，不替代逐项验收。上游默认关闭项仍须盘点，平台差异涉及实质取舍时交由用户确认。

## 当前差异状态

| 功能 | 当前实现 | 5.7.0 对齐状态 |
| --- | --- | --- |
| 首页首屏、导航、列表、分页 | 继承 Halo 版，修正资源和默认配置 | 待视觉比对 |
| 文章、标题、目录、代码工具栏 | 继承 Halo 版并修复基础行为 | 待逐项比对 |
| 手机菜单、主题模式 | 基础行为修复 | 待完整布局比对 |
| 分类、标签、归档、自定义页面 | 保留 Halo 页面 | 待逐项比对 |
| 搜索、评论 | Halo 官方 `PluginSearchWidget` / `PluginCommentWidget` 接入与停用回退（DEC-01） | 待按修订后的 PLG-02/03 验收；Algolia/DocSearch/12 家评论 SDK 不在 1.0 主题范围 |
| 友链、图库、瞬间 | 保留原有模板 | 未做插件集成验收 |
| Halo 2.26 插件公共布局 | 已提供 html(head, content)，合成插件自有模板、生命周期和共享资源通过 | 真实生态插件组合与完整跨浏览器验收继续推进 |
| 正文标签扩展（note/tabs/hide 等） | DEC-02：等效 HTML + 主题 CSS/JS，不解析 `{% %}`；series/flink 活数据延期 1.1 | 映射已定，待实现 |

首轮没有宣称全面对齐 5.7.0。独立 Hexo 参考站与固定内容夹具已经建立；截图差异仍须结合交互检查，不能只按相似度判断兼容性。

## 长期维护方式

官网采用真实 Halo 的文档与演示一体站，通过现有导航、置顶文章和侧栏突出项目介绍、快速开始和下载入口，第一版不新增首屏双按钮。页面清单、现有配置、内容发布及验收顺序见 [官网与文档演示站实施方案](DEMO-DOCS-SITE.md)。[首批内容](../site/README.md)已包含 10 篇教程、4 篇演示、5 个单页、素材来源和站点配置样例，已通过发布工具导入独立本地 Halo 样站；重复同步、后台冲突保护与本地页面验收已记录，搜索已启用，焦点恢复限制单独披露；文档演示站已部署至 hk 的 `https://butterfly.baizhukui.com/`，按 Release 更新并已同步 alpha.3；完整插件验收仍待完成，后续版本和 1.0 继续执行各自门禁。

采用“上游差异 issue → 单功能 PR → 实际页面验收 → 版本说明”的流程。Halo 只声明最低支持版本，不以未来版本号设置上限；降低最低版本须有实际验证，新 Halo 版本逐个登记测试范围与结果。核心资源随主题版本分发，插件按需接入；将 Halo 数据读取与页面表现逐步分开，降低后续上游移植成本。
