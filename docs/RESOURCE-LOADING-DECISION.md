# Halo 资源加载：alpha 发行裁定

2026-10-06，维护者明确裁定：[本仓库 #338](https://github.com/songxychn/halo-butterfly-next/issues/338) 属于需由 Halo 上游处理的问题，不应阻塞本主题发版。本次将其移出 alpha.3 发行阻塞项，作为已接受、必须披露的上游限制；本仓不再以定位或修复该问题作为本次发行前置条件。

## 影响与证据

固定 Halo 2.26.1 的本地/CI 环境出现静态资源请求挂起，可能使 CSS、JS、图片加载不完整，导致页面就绪、图片等待或截图超时。已有无主题/插件执行的纯 fetch 对照也出现挂起；该证据支持维护边界判断，但未确认具体上游根因，也没有官方修复版本证据。上游归类和发行取舍来自维护者裁定，不冒称 Halo 官方已确认根因。

- 历史 macOS、Linux 报告及原始失败继续保留。
- 本次 `1951fef` / `ad051bff` 的 Linux 检查仍为 108/120，不改成 120/120，也不把整体结果改成通过。
- 例外仅覆盖 #338 已记录的原生资源挂起及其直接就绪超时；其他请求失败、主题自身错误、资源字节不符或新缺陷仍须分别判断，不因同处一个失败报告而自动获准。

## 发行处理

发行说明和机器记录必须列出本限制、固定环境及证据链接。删除 `blockers` 中的 #338，单独记录维护者接受裁定；保留检查断言、非零退出、原始 `failed` 状态和矩阵未通过项，不修改主题或 Halo 来掩盖失败。

这项裁定解除 #338 对当前 alpha 发行的阻塞，不代表所有真实 Halo 场景已经通过，不解决继承 lazyload 的许可材料缺口，也不替代最终候选审查与维护者发布确认。当前总体 `decision` 仍依据其他未完成事项维护；不因单项例外写成 `approved`。

本次不发布 tag/Release，不修改或向 Halo 上游仓库提交内容。若以后采用 Halo 官方修复，需按实际版本重新验证后才能声称问题修复；当前不承诺修复时间。
