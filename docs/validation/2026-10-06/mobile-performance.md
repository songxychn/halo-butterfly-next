# 移动端首屏性能优化

## 具体实现

- 共享主题图片片段与侧栏头像使用原生 `loading="lazy"`、`decoding="async"`，保留真实 `src`、失败回退和布局。覆盖卡片、上下篇、相关文章与侧栏；不改写作者正文中的任意图片 HTML，不代表上游懒加载配置全部实现。
- 首页/文章顶图按实际配置预加载；共享布局在页面配置之后内联小型 CSSOM 初始化，将有效背景写入 CSS 变量。背景不再等待页面增强包或额外的 `Image.onload`；关闭顶图、空 URL 时不发出这条预加载。
- 将当前选中的小型 Loading 实现内联；正文末尾的主题事件释放遮罩，保留 DOMContentLoaded 回退、晚加载识别及一次性结束。保留独立 Loading 文件供插件公共布局兼容使用，公共布局未纳入本轮性能结论。
- 关闭 JavaScript 时显示服务端正文；默认光标的两条规则内联，避免单独阻塞请求。手机标题/副标题入场动画缩短为 0.2 秒，结束后的字体、位置与顶图尺寸不变，桌面动画不变。

外部主题 JS 统计不包括内联代码：两个路由的初始内联脚本均增加 2,065 字节，首页 HTML 增加 3,008 字节、长文增加 2,690 字节。传输量统计已计入 HTML 和所有实际请求资源，不把代码移入 HTML 当作代码消失。

参考 [Halo 主题模板](https://docs.halo.run/developer-guide/theme/template-variables)及 [Google LCP 优化指南](https://web.dev/articles/optimize-lcp)。

## 复验与范围限制

专属运行目录为 `.runtime/mobile-performance/`，Halo 回环端口 18341；报告、LHR、trace、DevTools 网络文件和前后输入快照的摘要均列入机器记录，运行目录不进入 Git。性能 CPU 锁覆盖每次完整采样，期间未同时构建或批量运行浏览器。服务端每路由先 3 次 HTTP 热身，随后每个样本使用全新独立 Chrome / 空 profile。

本轮使用 comparison 的照片配置与固定长文，停用全部可选插件；限定核对主题 JSON、文章发布字段/正文、固定资源及 Halo JAR，不替代正式默认值/系统/菜单/用户预检。固定 Lighthouse 将 `zh-CN` 解析成 `zh`，限定运行器按其官方 `lookupLocale` 检查原始 LHR，仅在内存克隆上归一化 locale 供既有校验器使用，原始报告不修改。

已安装真实夹具与浏览器依赖后，可复跑核心浏览器检查：

```sh
node scripts/perf/core-browser.mjs --base http://127.0.0.1:18341 \
  --output .runtime/mobile-performance/browser-recheck/report.json
```

限定性能命令为 `node .runtime/mobile-performance/measure.mjs baseline` / `node .runtime/mobile-performance/measure-final.mjs candidate-final`，双方必须分别切换对应包并使用全新输出目录；运行器和准备脚本的字节摘要已保存。完整采样规范仍见 [PERFORMANCE.md](../../PERFORMANCE.md)。本轮性能采样没有推荐插件组合、图库/公共插件页、160 样本、第三方失效矩阵、真机/iOS Safari 或 Linux 资源加载复验。非作者独立审查及 PR 提交 CI 另行跟踪，矩阵状态不提升为 verified。

剩余首屏资源包括首页约 201 KB 页面 CSS、74 KB 图标 CSS / 158 KB 图标字体，长文约 600 KB Prism 脚本（均为解压体积）。后续可继续按首屏 CSS、图标子集、代码高亮按需拆分分别实验；这些优化不计入本轮成果。
