## 正式性能矩阵

[机器记录](performance-full-matrix.json)覆盖基线/候选、默认/九插件推荐组合、四路由、两设备、每组五次，**160 次全部尝试，142 次有效、18 次无效**。基线为 72/80，当前候选为 70/80。失败不替换、不重试，诊断不回填。

候选的默认组合 40/40 有效；推荐组合首页 10/10、长文 9/10、图库 2/10、公共页 9/10。图库优先排查，其次是长文和公共页的请求停滞。双方共 8 次达到原 Lighthouse 约 45 秒导航上限，另外 10 次在较短采集截止时仍有请求未完成，后者需结合单独观察判断，不能直接称为正常延迟或 45 秒超时。

当前可独立判定的 **12/16 个候选预算组合全部达标**，可匹配的 **9/16 个基线/候选组合未超回归与体积预算**；缺失组合仍阻止 PERF-01/02/03 通过。默认手机首页 LCP 中位数从 4.05 秒降至 2.03 秒，默认手机长文约 2.03 秒。已有优化有效与加载可靠性尚未解决同时成立，不能只展示成功样本的速度。

[固定 10 例追加观察](performance-navigation-observations.md)中，基线首页桌面与候选图库手机分别出现请求在 Lighthouse 返回后继续等待 20 秒仍未响应。两者各自的浏览器请求、复用连接、客户端端口与 Java 接收队列已对应，支持服务端未继续读取这些连接；其余 8 例本轮未复现。没有运行时补丁/回滚对照，不能将全部 18 个正式失败归于同一根因。

## PR418 合并后的图库定位

PR #418 经再次独立审查后合并为 `9c561390ab39228b840057cb2f325ebe2f32d398`，合并 CI 通过。随后在同一产品包上执行[图库专项诊断](gallery-loading-diagnosis.md)：六次不执行前端 JavaScript 的真实资源回放中，顺序模式 1/3 完成、两次第三响应超时，主动排队模式 0/3；另三次固定 Chrome 图库观察有两次图片持续未响应。两类诊断均不回填正式性能样本。

两次新的浏览器失败均已对应到服务端实际缓冲、排空及后续连接未读取路径。Chrome 顺序发送不保证服务端的待完成响应计数已清零；此次日志命中的是 `pendingResponses > 1` 分支，并非调查前假设的 `existingOps` 分支。不同案例的前序 CSS 来自不同官方插件，不能把某个插件或图库前端脚本直接认作根因。该定位不代表已修复，也不把全部历史失败一概归因；产品、官方插件及预算保持不变。

## 图库因果确认与兼容缓解

后续[固定 A/B/A 因果对照](gallery-root-cause-and-options.md)在独立新批次执行 18 次协议和 9 次浏览器观察：顺序协议三阶段均 3/3；排队协议为 0/3 → 3/3 → 0/3；图库页面网络完整性为 1/3 → 3/3 → 1/3。仅改变读取恢复补丁即可消除并在撤回后重新出现故障，支持本批案例与 #338 / Halo #10359 同因。九例的 20 张图库网格图片都已加载，失败来自页面其他图片请求，不能称作 Photos 插件网格渲染故障。

官方 Halo 2.26.1 原包设置公开属性 `server.netty.max-keep-alive-requests=1` 后，9/9 连接关闭与资源校验、3/3 图库网络完整性和 4/4 公开路由检查通过；这是增加建连成本的临时绕行，未做完整生态与性能验收。因果与缓解证据均经独立审查，前两轮隔离/准备失败单独保留。官方 JAR 已恢复、配置撤销、实验进程停止，未改主题或官方插件、未部署。Halo 2.27.0 的相关依赖与缺陷类仍与 2.26.1 同字节；正式修复路径及代理替代方案见报告。

## 后续优先级

1. **P0：加载可靠性。** 先处理推荐图库的高频失败，再关闭长文/公共页及历史受影响页面。当前官方 Halo 中连接队列问题仍可复现；正式依赖修复进入 Halo 后，需复放协议、受影响页面和完整矩阵。不能靠主题前端重试、实验替换 Halo 类或取消官方插件资源来宣布兼容修复。
2. **P1：性能与原生图片。** 解决加载阻断后重新执行独立、完整的正式性能集合，不把诊断或补跑样本拼入本批；补固定执行机 CI、作者图片各编辑入口初始 HTML、缓存来源和未覆盖图片配置。既有预算不调整。
3. **P2：既有组合与最终验收。** 继续合同中尚缺的官方插件生命周期/组合、RSS 阅读器、平台映射、实际 Safari/真机等证据。局部结果保持限定范围，不自动提升功能矩阵状态或宣布 1.0 可发布。

## 工具修正与证据归属

- 推荐性能组合补齐现有九个固定版本插件，计入官方评论和 KaTeX 的原有全站资源；默认组合只启用路由必需插件。采样前后检查实际运行状态及所有插件配置摘要。
- 同批前后检查复用一个内存认证会话，但各次重新读取真实 API 并核对当前用户，避免验收工具频繁登录触发 Halo 保护；不持久化 cookie、不修改认证限制、不重跑失败的 Lighthouse 样本。
- 性能采样运行器固定为 `b44dc00e346be008b6422e615a196ba5ea69cd2f`。分析器固定为 `b56e97f5ea72fc0547a269863ab6028bce0755eb`，逐个页面/设备/组合判断有效五次样本，基线或另一设备失败不再遮蔽候选已知预算失败；双方匹配、原始摘要和身份检查仍保留。
- 原始首次失败、采集器修正后的独立批次、工具版本和 raw 指纹分别记录。诊断不是正式预算样本，完整计划执行完毕也不等于门禁通过。

以上证据来自本机归属明确的回环实验室和独立无头浏览器；不控制用户浏览器，不触碰生产环境。完整原始报告保留在忽略的 `.runtime/` 与性能运行器 worktree 内，Git 只保存审查用结果和指纹，原始文件不是随 PR 分发的永久归档。
