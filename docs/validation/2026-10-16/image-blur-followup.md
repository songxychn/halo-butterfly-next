## 新补齐的范围

实际 Halo 2.26.1 独占实验室 `127.0.0.1:18855`，`native=true / field=post / blur=true`，三引擎 × 1440/390 宽度，共 6 个 JavaScript 场景；另有三引擎各一个 390 宽度无 JavaScript 场景。浏览器仅访问本地合成内容。复用已有 `native-fixture.py` 创建两篇唯一 owner 标记的文章、保存并恢复配置，新增 `scripts/images/check-blur.mjs` 采集以下状态：

- 在图片请求已发出且响应交付被拦截、尚未交付页面时，图片具有 `theme-image-pending` 和计算样式 `blur(50px)`；作者显式 eager 图片保持 eager 且不模糊。
- 放行同一响应后，确认原始响应 HTTP 200 及其摘要，原 URL 保留，图片成功解码；pending class 和 filter 均移除。
- 响应式 picture 的直接子结构和宽/窄候选正确；显式 404 回退成功后无模糊；没有回退的作者坏图保留原 URL、alt，且不残留模糊。
- 无 JavaScript 时没有 pending class/filter，正常图片和 picture 可加载，正文可读，作者未声明 loading 的图片仍不被假称为服务端 lazy。

新批次 **CSS 状态与加载/失败生命周期 9/9 通过**，不等于 `lazyload.blur` 整条能力验收完成。实际截图检查确认：原生图片尚未取得像素时是留白；这个选项给待加载图片施加 CSS filter，并不生成低清缩略图，也不能据此承诺“先显示模糊小图，再逐渐清晰”的体验。截图保存于机器记录中的本地路径，不提交二进制。
