# Halo 2.27.1 评论策略与即时挂载补验

固定产品源 `65876917bd7ff31b18455a3e48a205dd5e1ded76`，ZIP `7f91d07597b6fa35ee99e2adde573891c9dc9548a9e1a137f414c7d33d24e08a`，269 文件；官方 Halo 2.27.1、CommentWidget 3.3.2。候选只修复关闭评论懒加载时的即时挂载分支，未修改官方插件或提升最低 Halo 版本。明细和原报告摘要见[机器记录](comment-policies.json)。不发布 1.0。

## 修复与证据

关闭 PJAX 和 `comments.lazyload` 后，原模板仍调用官方初始化器；官方空占位位于视口外时，其内部 IntersectionObserver 仍延迟挂载。两次完整失败及一次限定诊断保留。文章、单页、Moment 现在统一使用已有评论片段，关闭懒加载时直接挂载官方公开 Web Component；懒加载/PJAX 分支原有行为保留。269 文件包逐文件核对，重建 ZIP 与冻结包一致。

三引擎 × 匿名手机视口/登录桌面视口，Post、SinglePage 各 48 项、Moment 42 项，共 **138/138 策略检查通过**。包含全局/主体关闭、仅系统用户、审核、私密评论、验证码表面及关闭上传/表情。审核和私密评论执行真实提交并检查发布可见性；验证码求解和开启上传不在此批内。各最终策略批原配置、插件和自有数据清理核验通过。

Post、SinglePage、Moment 的实际 UI 使用阶段各 **6/6**：编辑器输入、原生离开确认、草稿返回、提交、一次预先声明的回复 503、一次用户重试及刷新去重。18 个使用例的最终请求/控制台/页面错误数组又以新增独立函数复核通过，仅允许与确切注入请求对应的 503 控制台消息，不将晚到错误忽略。

## 恢复读取与原失败

Post 与 Moment 首批完整运行的恢复阶段各有一个 WebKit 超时，主报告仍为 failed。Moment 的只读点击诊断证明，自动滚动后的真实点击落在评论容器，未命中回复按钮；页面未发出该条回复请求。准备步骤现先将按钮滚入视口并等待字体就绪，再执行一次真实点击，原 20 秒超时和单次点击保留。

修正后 Post、Moment 各用六组 API 读取夹具，停用/恢复各三引擎通过；SinglePage 原 UI 批的停用/恢复各三引擎已通过。API 夹具不算作 UI 提交证据，新的局部通过不改判原失败。

首个六组读取夹具批在浏览器启动前遇到官方异步订阅轮换，原报告 failed、清理通过。准备门限仍为 30 秒，改为在其中要求订阅清单稳定两秒后进入测量；不重试浏览器失败，也不删除预存订阅。已有精确合成订阅允许官方更换名称/token，按语义核验且记录轮换，不声称字面身份未变。较早手工恢复批仍保留各自 recovery 说明，不用于替代最终严格批的恢复证明。
