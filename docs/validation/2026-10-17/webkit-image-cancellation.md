# WebKit 图片取消：文档归属诊断

PR #425 最终提交 `5a5a63d4c75d122570ebe2da602e6e51f070ed0b` 经两路独立复审，32 项证据引用与实际结果一致，验收工具没有改变 Halo／官方插件兼容性；已合并为 `cf41b1d6a264beda6cd93a4fede69a63d8e00e7b`，PR 与主线 CI 均通过。原[官方组合批次](plugin-combination-fixed-candidate.md)继续保持 **5/6、87/96**，不因本次诊断改判。

## 本次确定了什么

**正常离页也会产生 WebKit `cancelled`，并且取消可能早于新文档请求和提交。** 因此，仅凭错误文字、目标阶段标签，或失败时 loader 仍是当前文档，都不能认定为在页加载故障。要结合请求的真实文档／loader、导航策略事件、新文档请求和提交顺序判断；缺少这些证据时保留未知。

原失败没有保存文档归属，无法事后恢复。其图片取消早于 Moment 主文档请求 1 毫秒的时序与本次正常离页控制相符，但这不是原 Halo 请求因果相同的证明。目前没有证据要求修改灯箱、Halo 或官方插件，也没有将它归入 #338 连接缺陷。

## 三个本地受控对照

独立回环 HTTP 服务器和新建无头 WebKit 执行三个固定对照，均完成各自预期。它们不请求 Halo，不修改浏览器私有方法，也不伪造 requestfailed 事件；只用于确认分类所需证据。

| 场景 | 实际网络与页面结果 | 解释 |
| --- | --- | --- |
| 在页成功图片 | HTTP 200、load、naturalWidth>0 | 正常加载 |
| 在页真实 404 | HTTP 404、error、naturalWidth=0，文档未离开 | 真实在页资源失败；虽 requestfinished，仍必须失败 |
| 旧文档图片响应保持未完成，点击原生链接离页 | 图片自然 cancelled、无响应；新文档 200；取消先于 context 关闭 | 已知动作下的正常离页取消 |

第三例协议顺序为：导航策略事件 **31／32** → 图片取消 **33** → 新文档请求 **34** → 新文档提交 **36**。公共事件中取消在 `13:21:58.675Z`、新文档请求在 `.676Z`，context 关闭到 `.692Z` 才开始。失败时旧 loader 仍是已提交文档，解析器如实标 `during-current`；这个标签只描述状态，不表示在页缺陷，也不会豁免失败。404 和全部 requestfailed 都保留在账本。

## 工具、恢复与后续

新增的[独立诊断 profile 与离线解析器](../../../scripts/acceptance/combinations/DIAGNOSTICS.md)不改变默认六组验收。原始协议可能含会话资料，留在忽略目录并强制 0600；派生摘要只取白名单字段，不输出 cookie、headers、查询参数或脚本文本。离线初稿漏识别 WebKit 的 `StyleSheet` 拼写，114 条 CSS 类别为 null；已窄修并重新离线解析，旧摘要保留，没有增加浏览器样本。该修正不影响图片归属或失败计数。
