## 阅读器验证及隐私边界

真实 `reader` 公共 API 直接订阅本地 RSS，独立进程使用同一个 SQLite 依次完成：初次订阅并标记已读、更新已发布标题／正文、重复刷新不重复入库。三次记录保持同一 entry ID 和已读状态，更新阶段为 1 条 modified，重复阶段为 0 条 new／modified。转私密后再创建一个全新 reader 数据库，确认公开转私密的文章、原私密文章和草稿均未进入新订阅。

持续数据库有 14 条记录，其中 1 条为本轮已更新且已读的合成公开文章；新数据库有 13 条记录，不含本轮任何合成文章。独立审查以 SQLite 只读不可变模式核对内容及完整性，两个数据库均为 `ok`。

**持续数据库最后一次刷新发生在文章转私密之前，未测试既有订阅在转私密后再次刷新。** 已下载内容可能被订阅者保留；本次不能把数据库中的旧条目称为已验证的“转私密后刷新仍留存”，也不承诺撤回订阅者已经下载的内容。没有打开阅读器 GUI、渲染订阅正文图片或执行遥测图片请求。

## 实际卸载与恢复

独立批次依次卸载 Feed、恢复同版本官方 JAR，再卸载 Sitemap、恢复同版本官方 JAR。每次缺失期间首页返回 200，只隐藏对应入口，对应 XML 路由返回 404；重装后两个入口各一次，XML 可解析且链接无重复。插件资源 API 的 404 来自已审查的 `gone()` 轮询和运行记录，没有单独保存该 API 的原始响应；公开 XML 路由的 404 响应原文已归档并独立核验。

重装后的创建时间与原插件不同；恢复工具登记新的实例身份，不能把正常重建误判为内容变化，也不会接管未知替换实例。目标插件 JAR 文件名允许变化，字节必须匹配事前备份；插件配置存在性和 data、启停状态、spec、其他插件身份、原有正文 spec／发布快照、主题和系统配置均严格比较。重装为各目标一次，finally 对已登记实例恢复原启停状态，不再次安装。

两次主批各自清理 3 篇随机标记合成文章并核实 404；两插件原始状态均为停用，最终恢复停用。主批与卸载批的站点前后记录一致；独立审查还只读核对全部插件 JAR、官方 Halo JAR 和 269 个已安装主题文件。其他正在进行的验收可以继续复用该自有实例，本报告不声称整轮实验实例已经停止。

## 独立审查与保留范围

独立审查重新核对主批的 4 + 137 份 HTTP 原文、卸载批的 8 份响应，重算指纹并解析 XML／入口／canonical，同时检查夹具创建时间、SQLite 和恢复结果。工具预审发现的 `UpdatedFeed._asdict()` 不适用已在首次运行前改为 `dataclasses.asdict()`；不把尚未执行的工具问题记成产品失败。

本次工具保留一个采集字段局限：主批 `requests.path` 存储的是归档响应文件名，端点由阶段中的 `/rss.xml`／`/sitemap.xml` 键、调用代码和 XML 根节点辨识，不能直接把该字段当成请求 URL。原始报告不回填或覆盖。

本批只证明上述固定版本和本地场景；不覆盖其他插件版本、已有订阅转私密后再刷新、阅读器 GUI、完整浏览器组合或生产部署。Halo 连接问题继续等待官方修复；没有安装补丁 JAR、修改 keep-alive 参数、增加临时代理或降低性能门禁。
