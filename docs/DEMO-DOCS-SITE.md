# 官网与文档演示站实施方案

本方案面向项目维护者，定义第一版站点的页面、内容、主题配置和实施验收。采用一个真实 Halo 站，安装 Halo Butterfly Next，同时提供使用文档和功能演示。首页保留 Butterfly 的大图、文章卡片和侧栏，突出项目介绍、快速开始和下载入口。

方向已在 2026-10-05 的讨论中确认，第一版不新增首屏双按钮，复用现有导航、置顶文章和侧栏入口。目前已完成方案、19 篇正文草稿、站点清单、配置样例与 14 张 Pexels 摄影图片，见 [站点内容入口](../site/README.md)。内容发布工具与独立本地 Halo 样站已完成，文档与演示站已部署至 `https://butterfly.baizhukui.com/`（hk 独立实例）。2026-10-09 当前 alpha.4 安装包已公开，站点已同步该 Release，见[发布完成记录](validation/2026-10-09/alpha4-publication.md)。能力核对基于仓库提交 `ab4e3c6`，以下“已有”表示源码存在，不替代实际站点验收。

## 站点定位与第一版范围

网站使用主题自身的文章、目录、菜单和页面布局。教程按“效果、配置步骤、注意事项”组织，阅读文档的过程也能体验主题。项目介绍明确说明这是独立的 Halo 社区维护项目，保留上游署名。

第一版采用中文，包含 10 篇使用教程、4 篇演示文章、5 个信息单页，以及 Halo 原生列表页面。更新日志只录入有明确版本身份的内容，未发布候选明确标为预览说明，不制造发行记录。

第一版不包含在线修改全站配置的公共后台、多实例皮肤切换、多语言文档和多版本文档选择器。图库、瞬间和友链插件页留待对应组合验证后加入。普通浏览者无需登录即可阅读文档与体验主题；不提供共享管理员账号。

## 页面与导航

顶栏顺序为“首页、使用文档、功能演示、更新日志、预览说明、GitHub”。公开版本就绪后，“预览说明”改名为“下载主题”，仍指向同一个下载说明单页。没有实际日志时暂不显示“更新日志”，GitHub 指向[现有公开仓库](https://github.com/songxychn/halo-butterfly-next)。各项均为可直接访问的叶节点。当前菜单的分组节点负责展开，因此不把“使用文档”同时设计成分组按钮与总览链接。文档内部分类由总览页承担。

## 首页与阅读体验

首屏标题为 **Halo Butterfly Next**，简介为“Hexo Butterfly 主题在 Halo 的移植版本”简介使用静态本地文案，避免访客等待打字或外部文案请求。

快速开始通过置顶教程 `getting-started` 和文档总览进入；下载通过顶栏、侧栏公告和页脚进入 `download` 单页。所有下载入口先展示版本与安装说明，再提供实际安装包链接。首屏保持现有标题、简介和滚动入口。

首页列表置顶“第一次使用 Halo Butterfly Next”和“功能演示导览”。复用普通文章卡片；不新增另一套精选卡片组件。置顶排序由 Halo 内容配置承担，需要在样站检查两篇顺序、分页以及重复展示情况。教程手写简洁摘要，不让首页卡片显示文档目录和长代码片段。

视觉采用现有蓝色强调色、统一的横向封面和系统字体。首页高度与标题位置均留空，采用主题默认 `100vh` 和 `43%`。首屏铺满视口，窄屏应容纳换行标题、简介和滚动入口；优先通过现有配置适配小屏与横屏，无法满足时记录具体缺口再讨论，不用官网专属 CSS 隐藏问题。

文章保留标题、正文目录和主题现有顶图布局。当前文章设置只核实了顶图开关，尚未确认独立的高度配置；第一版先用现有布局，不承诺“文档专用封面高度”或逐篇侧栏控制。封面不应淹没正文，最终以样站桌面、窄屏实测调整。

侧栏公告展示当前演示主题版本、已验证的 Halo 版本和预览状态，并提供下载说明链接。版本文字与实际安装包同步更新；主题没有现成的专用版本卡片，第一版复用公告。文档入口复用作者按钮、总览页和导航，不开发自定义文档树卡片。

## 内容管理与发布

面向访客的内容已放在仓库 `site/content/`，配套 `site/assets/`、`site/manifest.json` 和 `site/config/theme-profile.json`；工程文档继续留在 `docs/`。`bun run site:check` 离线检查内容身份、交叉链接、素材摘要和配置字段，不连接 Halo。站点发布使用选定的内容与素材；源码仓库已公开并保留完整 Git 历史。

每篇内容至少记录稳定 ID、对象类型、slug、标题、分类标签、摘要、封面、适用主题版本及发布状态。正文采用 Markdown；发布工具转换为 Halo 可渲染的 HTML，处理标题锚点、图片路径、代码语言和站内交叉链接。URL 从 Halo 对象读取后回填链接映射，不能靠拼接 slug 猜测最终路由。

发布流程为“校验内容与素材 → 预览变更列表 → 同步受管理对象 → 发布 → 检查链接与页面”。第一版完成可重复的手动命令，自动发布留在此流程稳定之后。规则如下：

- 工具只管理本项目清单声明、带归属标记的文章、单页、分类标签、菜单及附件。遇到同名但不属于工具的对象时停止，不接管其他内容。
- 重复执行不产生重复对象；保存源内容摘要与上次发布状态。后台编辑与 Git 不一致时报告冲突，不静默覆盖；以 Git 为内容维护入口。
- 从清单移除一篇文章不自动删除线上对象；另行给出下线计划。失败后能够重试，未完成内容不出现在导航中。
- 主题升级和内容更新分开执行。发布文档不顺带安装主题、改变插件或替换整份站点配置。
- 主题配置样例不含密钥；凭据通过本地受限文件或运行环境提供。发布记录仅保存版本、提交、包摘要、内容摘要与结果。

展示站使用独立 Halo 实例与数据目录。本地对照实验室继续保留固定夹具与版本，避免官网内容更新破坏已有验收。首版文档只覆盖当前展示版本；升级时同步维护适用版本与变更说明，旧包对应说明保留在 Git 和发行材料中。

验收需要证明：两种主题模式下正文、导航和侧栏入口可读；键盘能访问主入口并看清焦点；站内链接无错误目标；下载入口与实际发布状态一致；插件缺失时不产生无效入口；资源加载没有未解释的失败。记录实际 Halo、主题、插件和包身份，保留已知失败与未测范围，不把无头视口检查表述为真机验收。

最终交付应包含可访问样站、可复现的内容与配置、对应主题包，以及检查记录。仅生成静态效果图或 HTTP 首页返回成功不算完成真实 Halo 演示站。
