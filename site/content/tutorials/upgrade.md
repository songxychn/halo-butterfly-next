# 升级主题与回退

适用：主题 ID 为 `halo-butterfly-next` 的同 ID 升级。当前 alpha.3 仍处于预览准备阶段，下载与版本状态见[预览说明](../pages/download.md)。

升级主题会更换模板和静态资源。它不是整站备份，也不保证所有自定义配置在任意旧版本之间都兼容。

## 升级前保存什么

保存当前可用的主题 ZIP、包摘要、主题完整配置，以及 Halo 和相关插件版本。同时准备覆盖数据库、附件和站点配置的可恢复备份。

通过熟悉的备份方式导出主题配置。使用 API 的维护者可以读取 `GET /apis/api.console.halo.run/v1alpha1/themes/halo-butterfly-next/json-config`；导出文件可能包含私人链接和自定义内容，不要发到公开讨论区。

先在测试站验证新包，至少检查首页、文章、菜单、搜索、评论以及自己经常使用的配置。

## 安装新版本

1. 阅读新版本说明，核对下载包的 SHA-256。
2. 在 Halo 主题管理中上传同 ID 的新主题 ZIP，执行主题更新。
3. 保留原有 Setting 与 ConfigMap，不要先删除主题再安装。
4. 打开前台检查实际版本、样式、图片与脚本是否更新。

GitHub 的 Source code 压缩包不能代替构建后的主题 ZIP。同名预览包也可能来自不同提交，应以版本说明中的包摘要区分。

## 验证数据和设置

核对文章、单页、评论和导航仍然存在。检查深浅色模式、手机菜单、正文目录、图片和代码工具栏。使用旧浏览器会话刷新一次，确认没有继续加载旧资源。

新增设置缺失时的回退行为与旧版本有关，不要把新版设置直接套到不认识它的旧包上。升级后如果出现变化，先记录具体配置和页面，再判断是否需要回退。

## 回退到已保存的旧包

在主题管理中上传此前保留的同 ID 旧 ZIP，更新回旧版，再核对原配置。必要时根据备份恢复配置；整份配置替换前先保存当前配置，避免用不完整 JSON 覆盖其他分组。

无法立即恢复显示时，可以先启用另一个已验证可用的主题。主题包回退不会自动回退升级后新增的文章或评论，也不能代替数据库和附件恢复。

原始 alpha.2 在关闭文章顶图时有已知元信息脚本问题；确需回退该旧包时，应保留文章顶图开启。旧包也须先确认来源和可用范围，当前不提供未经检查的旧版本公开下载。

从 `theme-butterfly` 切换到 Next 是另一条流程，请阅读[旧主题迁移](migration.md)。
